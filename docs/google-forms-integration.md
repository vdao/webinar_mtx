# Интеграция с Google Формами: автоматическая регистрация участников

Гайд по настройке связки «Google Форма → вебинар» без ручной работы:
человек заполняет форму, приложение регистрирует его на вебинар и мгновенно
получает письмо с **персональной ссылкой** на комнату.

```
Google Форма ──(отправка)──► Apps Script ──POST /hooks/{id}──► Приложение
                                │                                 │ регистрация,
                                │                                 │ генерация кода
                                │◄───── ответ {ok, link, …} ──────┘
                                │
                                └──MailApp──► письмо участнику с персональной ссылкой
```

Шаблон письма формирует и отправляет скрипт от имени вашей почты. Приложение
отвечает за регистрацию, уникальный код и доступ в комнату.

> Документ предполагает развёрнутое приложение с публичным адресом по HTTPS
> (см. README, раздел «Производство: HTTPS»). С `localhost` Google-скрипты
> работать не будут.

---

## 1. Проверка исходной инструкции: что верно, а что нет

Идея «Форма → Таблица → Apps Script → письмо» рабочая, но для этого
приложения её нужно скорректировать:

| Утверждение исходной инструкции | Вердикт |
|---|---|
| Ответы формы сохраняются в Google Таблицу | ✅ Верно, таблица полезна для истории, но для скрипта не обязательна |
| Скрипт открывается из формы: ⋮ → Apps Script | ✅ Верно. Важно: скрипт должен быть привязан **к форме** (тогда доступно `e.response`). У скрипта, привязанного к таблице, объект события другой (`namedValues`) — см. раздел «Нюансы» |
| `e.response.getRespondentEmail()` получает email | ✅ Верно, но работает только при включённом сборе адресов в настройках формы |
| Резервный способ: взять email из ответа по заголовку поля | ✅ Рабочий код |
| `MailApp.sendEmail` мгновенно отправляет письмо | ✅ Верно (с учётом квот, см. ниже) |
| **Скрипт сам генерирует 6-значный код доступа** | ❌ **Главное исправление.** Вход в комнату — только по персональной ссылке `/w/{slug}?c={код}`, которую генерирует **приложение** при регистрации. Случайный код из скрипта с комнатой никак не связан. Скрипт должен вызвать вебхук приложения и взять готовую ссылку из ответа |
| — | ❌ В инструкции нет вызова бэкенда, авторизации скрипта, секрета вебхука и настройки триггера — всё это добавлено ниже |

## 2. Шаг 1. Вебхук в приложении

1. Откройте админку → **Вебхуки** → создайте новый (например, «Google Форма —
   осенний вебинар»).
2. В настройках вебхука:
   - **Пресет путей**: «Другая система»;
   - **Путь к email**: `email` (поле `email` в корне JSON — так его отправляет скрипт);
   - **Путь к товару**: оставьте пустым;
   - **Вебинар по умолчанию**: выберите вебинар, на который регистрирует форма
     (если у вас несколько форм/вебинаров — создайте отдельный вебхук на каждый);
   - запомните **URL** (`https://ваш-домен/hooks/wh_…`) и **секрет**
     (`whsec_…`).
3. Проверьте кнопку **«Отправить тестовый запрос»** с payload:
   ```json
   {"email": "test@example.com", "name": "Тест Тестов"}
   ```
   В ответе должно быть `"ok": true` и `"link"` с персональной ссылкой,
   а на странице участников появиться `test@example.com` с именем.

Необязательное поле `name` (ФИО) сохраняется у участника и дальше попадает
в колбэк публикации записи (`NOTIFY_RECORDING_URL`).

## 3. Шаг 2. Google Форма

1. Создайте форму с вопросами:
   - **Email** — не нужен как вопрос: включите сбор адресов
     **Настройки → Ответы → Собирать адреса электронной почты →
     Вводимые респондентами**. Так email гарантированно валиден и попадает
     в `e.response.getRespondentEmail()`.
   - **ФИО** (короткий ответ) — необязательно, но полезно: имя сохранится
     у участника. Скрипт ищет поле, в заголовке которого есть «фио» или
     «имя» (регистр не важен).
2. Подключите Таблицу ответов (**Ответы → значок таблицы**) — для истории
   и контроля; скрипт будет работать и без неё.

## 4. Шаг 3. Скрипт

В редакторе формы: **⋮ (три точки) → Apps Script**, вставьте:

```javascript
// Загружается из «Свойств сценария» (Настройки проекта), а не из кода —
// чтобы секрет не лежал в теле скрипта.
function props() {
  return PropertiesService.getScriptProperties();
}

function onFormSubmit(e) {
  if (!e || !e.response) return;

  // 1. Email респондента (включите его сбор в настройках формы)
  var email = e.response.getRespondentEmail();
  if (!email) {
    console.error('Email не получен: включите сбор адресов в настройках формы');
    return;
  }

  // 2. ФИО — из поля с «фио»/«имя» в заголовке (необязательно)
  var name = '';
  var items = e.response.getItemResponses();
  for (var i = 0; i < items.length; i++) {
    var title = items[i].getItem().getTitle().toLowerCase();
    if (title.indexOf('фио') !== -1 || title.indexOf('имя') !== -1) {
      name = String(items[i].getResponse() || '').trim();
      break;
    }
  }

  // 3. Регистрируем участника в приложении через вебхук
  var resp = UrlFetchApp.fetch(props().getProperty('WEBHOOK_URL'), {
    method: 'post',
    contentType: 'application/json',
    headers: { 'X-Webhook-Secret': props().getProperty('WEBHOOK_SECRET') },
    payload: JSON.stringify({ email: email, name: name }),
    muteHttpExceptions: true
  });
  if (resp.getResponseCode() !== 200) {
    console.error('Вебхук вернул ' + resp.getResponseCode() + ': ' + resp.getContentText());
    return;
  }
  var result = JSON.parse(resp.getContentText());
  if (!result.ok) {
    console.error('Регистрация отклонена: ' + (result.reason || result.error || ''));
    return;
  }

  // 4. Письмо с персональной ссылкой (её сгенерировало приложение)
  MailApp.sendEmail({
    to: email,
    subject: 'Ваш доступ к вебинару «' + result.webinar + '»',
    body:
      'Здравствуйте' + (name ? ', ' + name : '') + '!\n\n' +
      'Спасибо за регистрацию на вебинар «' + result.webinar + '».\n\n' +
      'Вход в комнату — по вашей персональной ссылке:\n' +
      result.link + '\n\n' +
      'Сохраните письмо. Ссылка личная — не передавайте её третьим лицам.\n\n' +
      'С уважением,\nКоманда проекта.'
  });
}
```

Затем в редакторе скриптов: **Настройки проекта (шестерёнка) → Свойства
сценария → Добавить**:

| Свойство | Значение |
|---|---|
| `WEBHOOK_URL` | `https://ваш-домен/hooks/wh_…` |
| `WEBHOOK_SECRET` | `whsec_…` |

## 5. Шаг 4. Триггер и авторизация

1. Слева в редакторе скриптов откройте **Триггеры** (значок часов) →
   **Добавить триггер**:
   - функция: `onFormSubmit`;
   - источник: **Из формы**;
   - тип события: **При отправке формы**.
2. Google попросит авторизовать скрипт (доступы: отправка писем и внешние
   запросы) — подтвердите своим аккаунтом. Для обычного gmail-аккаунта может
   потребоваться «Дополнительные настройки → Перейти к проекту (небезопасно)»
   — это стандартное предупреждение о личном скрипте.

## 6. Шаг 5. Проверка

1. Откройте форму в режиме просмотра, заполните и отправьте.
2. Ожидаемый результат:
   - на почту приходит письмо с темой «Ваш доступ к вебинару «…»» и ссылкой
     вида `https://ваш-домен/w/{slug}?c={код}`;
     ссылка открывается и показывает плеер;
   - в админке на странице участников появился email с именем и той же
     персональной ссылкой;
   - в редакторе скриптов **Выполнения** — успешный запуск без ошибок.
3. Отправьте форму повторно с тем же email: письмо придёт снова **с той же
   ссылкой** (дубликаты не создаются, код не меняется).

## 7. Нюансы и ограничения

- **Квоты MailApp** (письма в день с одного аккаунта): обычный Gmail — 100,
  Google Workspace — 1500. Для крупных вебинаров используйте Workspace-аккаунт
  или вариант Б ниже.
- **Скрипт должен быть привязан к форме** (⋮ → Apps Script из редактора
  формы): только тогда в триггере доступен `e.response`. Если скрипт
  привязан к таблице, используйте `e.namedValues['Email'][0]` вместо
  `e.response.getRespondentEmail()`.
- **Секрет — в свойствах сценария**, не в коде: доступ к коду скрипта есть у
  редакторов формы/таблицы. Для интеграции создайте отдельный вебхук с
  «вебинаром по умолчанию» — компрометация такого секрета не даст ничего,
  кроме бесплатных регистраций на один вебинар (отзыв — перегенерация секрета
  в админке).
- Отправитель писем — аккаунт, владеющий скриптом; письма уходят мгновенно,
  но попадают в «Отправленные» этого аккаунта.
- Заблокированные в админке участники перестают пускаться по ссылке, но
  письмо при повторной отправке формы всё равно уйдёт (скрипт не знает о
  блокировке) — при необходимости ловите `created:false` и меняйте текст.

## 8. Вариант Б: отправка писем для ВСЕХ регистраций (Web App)

Если хотите, чтобы письма уходили не только с формы, но и при импорте CSV,
ручном добавлении и оплате — разверните Apps Script как **веб-приложение** и
подключите его к `NOTIFY_WEBHOOK_URL` (исходящий вебхук приложения).

1. В том же или новом проекте Apps Script добавьте:

```javascript
// Веб-приложения Apps Script не видят HTTP-заголовков, поэтому секрет
// передаётся query-параметром: NOTIFY_WEBHOOK_URL=…/exec?secret=ЗНАЧЕНИЕ
function doPost(e) {
  if (e.parameter.secret !== props().getProperty('NOTIFY_SECRET')) {
    return ContentService.createTextOutput('bad secret');
  }
  var ev = JSON.parse(e.postData.contents);

  if (ev.event === 'participant.registered') {
    MailApp.sendEmail({
      to: ev.email,
      subject: 'Ваш доступ к вебинару «' + ev.webinar_title + '»',
      body: 'Здравствуйте!\n\nВаша персональная ссылка:\n' + ev.link
    });
  }
  if (ev.event === 'recording.published') {
    MailApp.sendEmail({
      to: ev.email,
      subject: 'Запись вебинара «' + ev.webinar_title + '»',
      body: 'Здравствуйте!\n\nЗапись доступна по ссылке:\n' + ev.recording_url
    });
  }
  return ContentService.createTextOutput('ok');
}
```

2. **Развернуть → Новое развёртывание → Веб-приложение**:
   «Выполнять как: я», «Доступ: все, у кого есть ссылка». Скопируйте URL.
3. Добавьте свойство сценария `NOTIFY_SECRET` (придумайте длинное случайное
   значение) и укажите в `.env` приложения:
   ```
   NOTIFY_WEBHOOK_URL=https://script.google.com/macros/s/…/exec?secret=ВАШ_СЕКРЕТ
   NOTIFY_RECORDING_URL=…тот же или другой URL развёртывания…
   ```
   Обратите внимание: здесь секрет — произвольная строка, общая для `.env`
   и свойства сценария (подпись HMAC в этот вариант не передаётся из-за
   ограничения Apps Script).
4. После каждого изменения кода — **Развернуть → Управление развёртываниями →
   Изменить → Новая версия**, иначе работает старый код.

Ограничение варианта: письма по событиям идут из одной квоты MailApp;
Google-эндпоинт отвечает медленно (1–3 с), но приложение отправляет события
асинхронно и не блокирует регистрации.

## 9. Устранение неполадок

| Симптом | Причина и решение |
|---|---|
| Письмо не пришло | Смотрите **Выполнения** в редакторе скриптов: ошибка авторизации — перезапустите функцию вручную для выдачи доступов; квота исчерпана — придёт `Exceeded daily quota` |
| В логе `Вебхук вернул 401` | Неверный `WEBHOOK_SECRET` (свойство сценария). Сверьте с админкой; после перегенерации секрета обновите свойство |
| В логе `Регистрация отклонена: … не найден корректный email` | В настройках вебхука путь к email не `email`, либо выключен сбор адресов формы (`Email не получен` в логе скрипта) |
| Триггер не срабатывает | Триггер «Из формы → При отправке формы» не создан, либо скрипт привязан к таблице, а не к форме |
| `urlfetch` падает с ошибкой DNS/TLS | Приложение недоступно извне по HTTPS — проверьте reverse-proxy и `APP_URL` |
| Участник зарегистрирован, но без имени | Заголовок поля ФИО не содержит «фио»/«имя», либо поле не заполнено |
