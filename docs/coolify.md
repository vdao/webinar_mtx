# Развёртывание в Coolify

Coolify — self-hosted PaaS: сам termin'ит HTTPS (Traefik-прокси), хранит
переменные окружения, redeploy-ит по пушу. Для него в репозитории есть
готовый вариант стека: [`deploy/coolify/docker-compose.yml`](../deploy/coolify/docker-compose.yml).

Чем он отличается от корневого `docker-compose.yml`:

| | Корневой compose | Coolify-вариант |
|---|---|---|
| Приложение | порт `8080` на хосте | без published-порта; домен/HTTPS через UI Coolify (порт контейнера `8080`) |
| MediaMTX | конфиг из файла `mediamtx/mediamtx.yml` | конфиг через переменные `MTX_*` (bind-маунты файлов Coolify не любит) |
| Сборка | `build: .` как fallback | только готовый образ из GHCR |
| Порты наружу | 8080, 1935, 8889, 8189 | 1935, 8189 (WHEP-сигналинг идёт через приложение, 8889 не нужен) |

## Пошаговая настройка

### 1. Ресурс в Coolify

1. **Projects → ваш проект → Environment → + Add Resource → Docker Compose**
   (источник — этот git-репозиторий).
2. **Base Directory** — корень репозитория; **Docker Compose Location** —
   `deploy/coolify/docker-compose.yml`.
3. Coolify распарсит compose: все `${ПЕРЕМЕННЫЕ}` появятся в разделе
   **Environment Variables** (значения из `:-default` подставятся как
   начальные).

### 2. Переменные (минимум для старта)

| Переменная | Значение |
|---|---|
| `APP_URL` | `https://вебинар.домен` — публичный адрес (ссылки участников строются из него) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | доступ в админку (смените!) |
| `APP_SECRET` | `openssl rand -hex 32` |
| `POSTGRES_PASSWORD` | пароль БД (смените) |
| `MEDIA_HOST` | домен или публичный IP сервера — обязательно, это ICE-кандидаты WebRTC |
| `RTMP_URL` | `rtmp://вебинар.домен:1935/w` — показывается ведущему |
| `APP_TAG` | пинуйте релиз, например `0.0.2` (по умолчанию `latest`) |

Опционально: `NOTIFY_*` (вебхуки уведомлений), `OIDC_*` (SSO админки),
`S3_*` (публикация записей) — см. [`.env.example`](../.env.example),
состав переменных тот же.

### 3. Домен приложения

**Domains → Add domain**: сервис **app**, протокол `https`, ваш домен,
внутренний порт **8080**. Coolify выдаст сертификат Let's Encrypt и
заведёт маршрутизацию через свой прокси. DNS-запись домена должна указывать
на сервер.

### 4. Deploy

Нажмите **Deploy**. Первичный запуск: поднимутся `db` → `app` (миграции
применятся автоматически) → `mediamtx`. Здоровье видно в UI (healthcheck'и
уже настроены в compose).

### 5. Проверка

- `https://вебинар.домен/admin` — админка;
- в настройках вебинара появится RTMP-адрес — подключите OBS;
- персональная ссылка участника открывает комнату и плеер.

## Потоковая составляющая — что идёт мимо прокси Coolify

| Порт | Трафик | Через что |
|---|---|---|
| 443 | админка, комнаты, WHEP-сигналинг, вебхуки | прокси Coolify (Traefik) |
| 1935 | RTMP от ведущего (OBS) | напрямую в `mediamtx` |
| 8189 tcp/udp | медиа WebRTC (браузер ↔ mediamtx) | напрямую, NAT-пробивка ICE |

Видео **не проходит** через прокси и приложение — нагрузка стриминга ложится
на MediaMTX, приложение только авторизует. Если сервер за жёстким firewall
и UDP закрыт — tcp 8189 покрывает подключение (с чуть большей задержкой);
для минимальной задержки откройте UDP.

## Обновления

- Изменить `APP_TAG` на новый релиз → **Redeploy** (Coolify сделает
  `pull` + `up -d`, миграции применятся сами).
- Включите в Coolify вебхук/автодеплой на ветку, если хотите обновляться по
  пушу. Учтите: GitHub Actions `deploy.yml` (SSH-деплой) и Coolify —
  взаимоисключающие варианты: при деплое через Coolify переменную `DEPLOY_HOST`
  не задавайте.

## Бэкапы

- БД: том `pgdata` — подключитесь к серверу и снимайте `pg_dump`
  (или добавьте отдельный сервис бэкапа в compose).
- Записи вебинаров живут в S3 (при настроенных `S3_*`), локальный том
  `recordings` — временный, MediaMTX чистит его сам (7 дней).

## Частые вопросы

**Видео не подключается (плеер «Подключение…» бесконечно)** — почти всегда
`MEDIA_HOST`: он должен быть доменом/IP, доступным **из браузера участника**,
а не внутренним именем контейнера.

**404 на `/admin`** — домен назначен не тому сервису или указан не тот порт
(нужен внутренний `8080`).

**RTMP не проходит** — порт `1935` опубликован (есть в compose), проверьте
firewall сервера и `RTMP_URL` в переменных.

**`failed to read dockerfile: open Dockerfile: no such file or directory`** —
ресурс собрался как сборка образа, а не как compose-стек: проверьте два
момента. Во-первых, ресурс должен быть типа **Docker Compose** (не
Application с build pack). Во-вторых, **Docker Compose Location** должен
указывать на `deploy/coolify/docker-compose.yml` — в корневом
`docker-compose.yml` есть секция `build: .` (для локальной разработки),
поэтому Coolify пытается собирать образ и не находит Dockerfile.

**Хочу `network_mode: host` для mediamtx** — можно отредактировать compose
в Coolify (он хранит свою копию): уберите `ports:` у mediamtx и добавьте
`network_mode: host`; тогда `MTX_AUTHHTTPADDRESS` должен ссылаться на
достижимый адрес приложения, а не `http://app:8080`.
